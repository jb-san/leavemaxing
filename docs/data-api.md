# Data for machines: JSON, deep links, llms.txt

Everything here is static and is produced by `pnpm build`, so Cloudflare Pages serves it from `dist/` like any
other file. It needs no API key and doesn't change between builds unless the data or the code does.

## `/data/best/{cc}/{year}.json`

Best bridges and the recommended plan for one country and year. `cc` is the lowercase ISO 3166-1 code used in
page URLs (`/de/2027/` has `/data/best/de/2027.json`). Files exist for every country with holiday data and each
year the planner offers on the build date: the current year and the next two (`bestDataYears()` in
`src/lib/bestData.ts`). That is about 620 files, 3.6 MB in all.

Generated by the static endpoint `src/pages/data/best/[cc]/[year].json.ts` from `bestDataFile()` in
`src/lib/bestData.ts`, which uses the same engine and settings as the pages. The numbers match the page they
belong to:

- `bridgeDays` and `bestBreaks[0]` are the count and the best bridge the page's FAQ gives.
- `recommendedPlan` uses the leave days of the country's localized bridge-day page (25 for Sweden, 20 for
  Germany), or 20 where there is no localized page, the balanced style, and today as the first day leave can be
  taken. It is the plan the localized page (and its FAQ) shows. The English page `/{cc}/{year}/` always uses 20,
  so for a country with a different local default, its numbers differ from `recommendedPlan`.
- `generatedAt` is the build date, which is also the visible "last updated" date and `dateModified` in the
  pages' structured data.

```jsonc
{
  "version": 1,
  "country": "SE",
  "countryName": "Sweden",
  "year": 2027,
  "region": null,                     // always null: files are national
  "generatedAt": "2026-11-24",        // build date (UTC)
  "holidays": 16,                     // national public holidays in the year
  "publicHolidays": [{ "date": "2027-01-01", "name": "New Year's Day" }],
  "bridgeDays": 5,                    // working days in a 1–2 day gap next to a holiday
  "bestBreaks": [                     // bridges, best first (days off per leave day, then length); at most 10
    {
      "start": "2027-05-06",          // first day off
      "end": "2027-05-09",            // last day off
      "leaveDays": 1,
      "leaveDates": ["2027-05-07"],   // the days to take
      "daysOff": 4,                   // calendar days in a row, weekend and holidays included
      "efficiency": 4,                // daysOff / leaveDays, 2 decimals
      "holidays": [{ "date": "2027-05-06", "name": "Ascension Day" }]
    }
  ],
  "recommendedPlan": {
    "leaveDays": 25,                  // leave days available
    "style": "balanced",
    "leaveUsed": 25,
    "daysOff": 58,                    // days off in breaks that use leave
    "multiplier": 2.32,
    "longestBreak": 11,
    "breaks": [                       // same fields as bestBreaks, without leaveDates
      { "start": "2026-12-31", "end": "2027-01-10", "leaveDays": 4, "daysOff": 11, "efficiency": 2.75, "holidays": [{ "date": "2027-01-01", "name": "New Year's Day" }] }
    ]
  },
  "links": {
    "page": "https://leavemaxxing.com/se/2027/",
    "localized": ["https://leavemaxxing.com/sv-se/klamdagar-2027/"],
    "planner": "https://leavemaxxing.com/se/2027/?d=25"
  },
  "source": "Public holidays from date-holidays (CC BY 3.0), planned by leavemaxxing."
}
```

Holiday names are the English names from date-holidays. Dates are ISO `YYYY-MM-DD`. A break can start or end in
the neighbouring year (a Christmas break, say). `version` changes when a field changes meaning or goes away; new
fields can appear without it.

Pages point at their file with `<link rel="alternate" type="application/json" href="/data/best/{cc}/{year}.json">`:
the country-year pages and the national localized bridge-day pages, for the years that have a file. Regional pages
don't, since the files are national.

## `/data/{cc}/{year}.json`

The raw public holidays the planner loads (`scripts/build-data.ts`). Not a stable format: it follows what the
planner needs.

## Deep links

The planner hydrates from URL parameters on the home pages (`/`, `/{locale}/`), country pages (`/{cc}/`,
`/{cc}/{year}/`) and bridge-day pages. Two forms work, and can be mixed:

| Readable  | Share key | Value                                                       |
| --------- | --------- | ----------------------------------------------------------- |
| `country` | (path)    | ISO code, any case: `DE`                                    |
| `year`    | (path)    | A year with holiday data: `2027`                            |
| `region`  | `r`       | Region code, any case: `BY`                                 |
| `days`    | `d`       | Leave days, 0–80                                            |
| `style`   | `s`       | `weekends`, `balanced` or `long`                            |
| `months`  | `m`       | Preferred months, dot-separated: `7.8`                      |
| `yearStart` | `ys`    | Month the leave year starts, 1–12                           |
| `min`, `max` | same   | Shortest and longest break                                  |
|           | `ww`, `lk`, `bk`, `co` | Work week, and days kept as leave, blocked, or off (share links only) |

- `/?country=DE&region=BY&year=2027&days=25&style=long` opens that plan on the home page.
- `/de/2027/?d=25&r=BY&s=long` is the same plan in the share format, which is what the planner writes to the
  address bar and the share dialog.
- **Precedence**: when a link has both forms of a setting, the share key wins (`?d=30&days=25` plans 30 days).
  The share format is what the planner writes and what link previews read.
- On a plan page, a `country` or `year` that differs from the page opens that plan's own page with the same
  settings (`/se/2027/?country=DE&year=2028&days=12` goes to `/de/2028/?d=12`; a localized page goes to its own
  page for the other year).
- Invalid values are ignored, and the planner says that some settings in the link weren't valid.
- Canonical, hreflang and `og:url` stay the clean path. Shared-link previews (`functions/_middleware.ts`) accept
  `days` like `d`; a link with other settings, or another country or year, keeps the page's own preview.

Parsing lives in `fromLink()` and `fromQuery()` in `src/lib/settings.ts` (tests: `src/lib/settings.test.ts`).

## `/llms.txt` and `/llms-full.txt`

Written after the build by `integrations/llms.mjs` from the build's page list, filtered with the sitemap's rule
(`inSitemap()` in `src/data/sitemap-config.ts`). Titles and descriptions come from the built HTML. `llms.txt`
describes the site, the method, the key pages, these data files and the deep-link format; `llms-full.txt` lists
every indexed page with its title and description.
