# Together Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `/together/` page where a group with no accounts finds dates everyone can take off. Each member's settings are end-to-end encrypted and synced through one Cloudflare Durable Object per group.

**Architecture:**
- The static Astro site gets one React island that reads the URL fragment, encrypts and decrypts records with AES-GCM, and scores windows locally.
- A separate Worker in `worker/` routes `/api/together/:groupId` WebSockets to a SQLite-backed Durable Object. The Durable Object stores opaque envelopes and secret hashes, and enforces write rules.
- Every decision the server makes lives in a pure module (`worker/src/rules.ts`). The same module powers the fake server in the client session tests.

**Tech Stack:** Astro 7, React 19, TypeScript 6, Tailwind 4, Vitest 5, Playwright, Biome, Cloudflare Workers + Durable Objects (wrangler 4), `uqr` for QR codes.

**Spec:** `docs/superpowers/specs/2026-10-17-together-design.md`

## Global Constraints

- **Secrets:** all secrets live only in the URL fragment and localStorage, never in a path, query string or request body, except as a `secret` sent for write permission.
- **Sizes:**
  - `groupId`: 10 random bytes.
  - `groupKey`: 16 bytes (AES-128-GCM).
  - `memberId`: 6 bytes.
  - `memberSecret` and `adminSecret`: 16 bytes each.
  - IV: 12 bytes.
  - All of the above are encoded as base64url without padding.
- **Limits:** 20 members per group, 16 KB per envelope (measured as `JSON.stringify(env).length`), and 30 messages per 10 s per socket.
- **Expiry:** delete 60 days after the last day of the group's months, or 180 days after the last write, whichever comes first.
- **Ranking:** top 8 windows shown. Trip length is limited to 3–21 days.
- **Merging:** highest `version` wins per `(kind, id)`. A new version is `Math.max(previous + 1, Date.now())`.
- **Copy rules** (existing design system): sentence case, no all-caps labels, no middle dots, no `→` in UI copy, plain verbs. Lime means leave and sun means holidays. Inputs are 16px on mobile.
- **Exact copy from the spec:**
  - "Scan to join {name}"
  - "This one is just for you. Anyone with it can change your answers."
  - "This link is incomplete. Ask for the invite again."
  - "This group no longer exists"
  - "Start a new group"
  - "You were removed from this group."
  - "This group is full (20 people)."
  - "Slow down a moment."
  - "Works for everyone"
  - "Add to my plan"
  - "Propose dates"
  - "Use on another device"
  - "{name} invited you to {group}"
- **Dependencies:** the only new runtime dependency is `uqr`. New dev dependencies are `wrangler@4` and `@cloudflare/workers-types`.
- **Analytics:** only `together_create` and `together_join`, with no properties.
- **Language:** Together v1 is English only. Its UI strings live in `src/components/together/copy.ts`, not in the i18n catalog. Reused planner components (`CountryPicker`, `Calendar`, `Sheet`) fall back to English through `useI18n()` when there's no `I18nProvider`. The one exception is the nav label: add `navTogether` to `Copy.chrome` in `src/i18n/types.ts`, `src/i18n/en.ts` ("Together") and the 12 base locale files in `src/i18n/locales/` (the regional variants inherit). `src/i18n/catalog.test.ts` enforces this.
- **Blocked days override weekends and holidays:** this is already the planner's rule (`buildTimeline` in `src/lib/planner/plan.ts`). A member can block any day, and a blocked day is never off for that member.

### Two deliberate deviations from the spec, kept small

1. **No `hello` message.** The server sends `snapshot` as soon as a socket connects. `hello` carried nothing the server needs.
2. **The group `put` carries a plaintext `until` (ISO date, the last day of the group's months),** so the Durable Object can schedule expiry. The server can't read the encrypted months.

## Review Focus

1. **Missing holiday data.** A member's country has no holiday file for a year the group spans (`loadHolidayFile` resolves `undefined`). Expected: scoring continues with weekends only, and there's no crash. The test lives in Task 2.
2. **No window survives.** Everyone has blocked days or a small allowance. Expected: an empty ranked list with direction ("No dates work for everyone in these months. Widen the months or the trip length."), not a blank page. Tested in Task 2 for the empty result and Task 8 for the copy.
3. **Link mangled by a chat app.** The fragment arrives with a trailing `.`, `)` or whitespace, or percent-encoded. Expected: it still parses. Tested in Task 1.
4. **Valid but malformed record.** A member writes a correctly encrypted record with garbage votes, proposal keys, or an `end` before `start`. Expected: invalid entries are dropped on decrypt, and the rest of that member's record is used. Tested in Task 1 (`sanitizeMember`) and Task 2.
5. **Same member in two tabs.** Both write. Expected: the `stale` reply bumps the version and resends, the newest edit wins, and there's no loop. Tested in Task 5.

```ts
export interface ScoreMember { id: string; record: MemberRecord; holidays: HolidayDay[] }
export interface Helper { memberId: string; day: DayNum; name: string }
export interface ScoredWindow { key: WindowKey; start: DayNum; end: DayNum; length: number; score: number; costs: Record<string, number>; flagged: string[]; helps: Helper[]; proposedBy: string[] }
export interface Scored { ranked: ScoredWindow[]; proposals: ScoredWindow[]; agreed: ScoredWindow[] }
export const TOP_N = 8;
export const FAIRNESS = 0.5;
export function windowKey(start: DayNum, end: DayNum): WindowKey;
export function groupRange(g: GroupRecord): { start: DayNum; end: DayNum }; // first day of first month to last day of last month
export function costFor(m: ScoreMember, start: DayNum, end: DayNum): number;
export function scoreWindows(group: GroupRecord, members: ScoreMember[], today: DayNum): Scored;
```

The algorithm (the signature doesn't determine it):
1. Candidates: start from `max(groupRange.start, today + 1)` to `groupRange.end`, with every `len` in `minLength..maxLength`.
2. A day is off for a member if it's not in their `blocked` days and is a non-working day in their `workWeek`, one of their holidays, or in their `customOff`.
3. Extend the window backwards and forwards while the neighbouring day is off for every member. If the extended length is over `maxLength`, drop the candidate.
4. Reject the window if it includes any member's `blocked` day, or if `costFor > allowance` for anyone.
5. Score = `length * n / (sumCost + 1) - FAIRNESS * (maxCost - minCost)`.
6. Dedupe by key. Sort by score descending, then earlier start. Greedily keep a window unless it overlaps an already-kept one by more than half of the shorter window's length. Stop at `TOP_N`.
7. `proposals`: the union of members' `proposals`, scored with the same formula and never rejected. `flagged` lists the members who are blocked or over their allowance. `proposedBy` lists who proposed it.
8. Drop from `ranked` any key that also appears in `proposals`.
9. `agreed`: every key where all members voted `"yes"`, scored like proposals, sorted by score.
10. `helps`: each member's holidays that fall on their working weekdays inside the window.

- [ ] **Step 1: Write failing tests.** Build fixtures with `dayNum` and a standard Mon–Fri week:
  - **`costFor`:** a German member with a holiday on Fri 2027-05-14 is charged 4 for Mon 10–Sun 16 May, and a Spanish member without it is charged 5.
  - **Blocked and allowance:** a window touching a member's blocked day is absent from `ranked`. With `allowance: 2` and `minLength: 9`, `ranked` is empty (`[]`, no throw).
  - **Fairness:** two equal-length windows, one costing members `{a:2, b:6}` and the other `{a:4, b:4}`. Expected: the second ranks above the first.
  - **Extension:** a candidate starting on a Monday after a weekend both members have off starts on the Saturday instead.
  - **Dedupe:** two windows overlapping by 6 of 9 days keep only the higher score. `ranked.length <= 8`.
  - **Proposals:** a proposal covering a blocked day appears in `proposals` with that member in `flagged` and is not in `ranked`.
  - **Agreed:** all `"yes"` on a key puts it in `agreed`. One `"maybe"` keeps it out.
  - **Missing holiday data:** a member with `holidays: []` still scores (weekends only).
  - **Invalid data:** a member whose record went through `sanitizeMember` with garbage votes still yields valid `agreed` for the remaining good votes.
  - **Past dates:** candidates never start on or before `today`.

export interface Room { envs: Map<string, Envelope>; hashes: Map<string, string>; adminHash: string | null; removed: Set<string>; until: string | null; lastWrite: number }
export function emptyRoom(): Room;
export type Outcome =
  | { ok: true; broadcast: ServerMsg; dirty: string[] }  // storage keys to persist: envKey(...), `hash:${id}`, "admin", `tomb:${id}`, "until", "lastWrite"
  | { ok: false; reply: ServerMsg };
export function parseClientMsg(raw: string): ClientMsg | null;
export function applyPut(room: Room, msg: PutMsg, now: number): Promise<Outcome>;
export function applyRemove(room: Room, msg: RemoveMsg, now: number): Promise<Outcome>;
export function snapshot(room: Room): ServerMsg;
export function expiresAt(room: Room): number | null; // ms; null if the room is empty
export interface RateState { start: number; count: number }
export function rate(state: RateState | null, now: number): { ok: boolean; state: RateState };
```

Rules:
- **Envelope too large:** returns `limit`.
- **Group `put`:**
  - When `adminHash` is null, it requires `secretHash`, which must equal `hashSecret(secret)`. That registers the admin.
  - Otherwise `hashSecret(secret)` must equal `adminHash`, or it returns `auth`.
  - `until` (ISO date) is stored when present.
- **Member `put`:**
  - With no group envelope yet, it returns `gone`.
  - A removed id returns `auth`.
  - An unknown id needs `secretHash` matching `hashSecret(secret)`, and returns `limit` if 20 members already have hashes.
  - A known id must match its stored hash, or it returns `auth`.
- **Any `put`:** a `version` less than or equal to the stored version returns `{ code: "stale", id, version: storedVersion }`.
- **`applyRemove`:** needs the admin secret. It deletes the member's envelope and hash, adds a tombstone, and broadcasts `removed`.
- **`expiresAt`:** `min(until + 60 days, lastWrite + 180 days)`, using `lastWrite` alone when `until` is null.

// store.ts: same try/catch read/write pattern as src/lib/storage.ts; keys "lm:together:v1:<groupId>" and "lm:together:cache:v1:<groupId>"
export interface Membership { groupId: string; key: string; memberId: string; secret: string; admin?: string; groupName: string }
export function loadMembership(groupId: string): Membership | null;
export function saveMembership(m: Membership): void;
export function forgetMembership(groupId: string): void;
export function loadCache(groupId: string): Envelope[];
export function saveCache(groupId: string, envs: Envelope[]): void;

// session.ts
export interface SocketLike { readyState: number; send(data: string): void; close(): void; onopen: (() => void) | null; onmessage: ((e: { data: string }) => void) | null; onclose: (() => void) | null }
export type Status = "connecting" | "online" | "offline";
export type SessionError = "incomplete" | "gone" | "removed" | "full" | "rate" | null;
export interface GroupState { status: Status; group: GroupRecord | null; members: Map<string, MemberRecord>; me: string | null; isAdmin: boolean; error: SessionError; loaded: boolean }
export const BACKOFF_MS = [1000, 2000, 5000, 10000, 30000];
export function socketUrl(groupId: string, loc?: Pick<Location, "protocol" | "host" | "hostname">): string; // localhost/127.0.0.1 → ws://localhost:8787/api/together/<id>; else wss://<host>/api/together/<id>
export class GroupSession {
  constructor(link: InviteLink | PersonalLink, deps?: { socket?: (url: string) => SocketLike; now?: () => number; timers?: { set: typeof setTimeout; clear: typeof clearTimeout } });
  readonly state: GroupState;
  subscribe(fn: (s: GroupState) => void): () => void;
  create(group: GroupRecord, me: MemberRecord): Promise<void>; // only valid for newGroup() links
  join(me: MemberRecord): Promise<void>;
  updateMe(patch: Partial<MemberRecord>): Promise<void>;
  updateGroup(patch: Partial<GroupRecord>): Promise<void>; // admin only
  removeMember(memberId: string): void; // admin only
  personalLink(): PersonalLink | null;
  close(): void;
}
```

Behaviour:
- **Identity:** a `PersonalLink` in the fragment overrides `loadMembership`, and is saved as the membership.
- **On start:** decrypt `loadCache` into state first (so it works offline), then connect. `snapshot` replaces the cache.
- **Edits are optimistic:** state updates, the envelope is sealed with `nextVersion` and sent, or queued while the socket isn't open. The queue is flushed on open.
- **On close:** reconnect with `BACKOFF_MS` (the last value repeats). Status goes to `"offline"` after the first failed attempt.
- **Errors:**
  - `stale` for my own record: re-seal with `nextVersion(version)` and resend, at most 3 tries per edit.
  - `gone`: an empty snapshot with no group envelope when not creating → `error: "gone"`.
  - `removed`: my id is in `removed` → `error: "removed"` and `forgetMembership`.
  - `limit` on join → `"full"`. `rate` → `"rate"`.
- **Broken data:**
  - A fragment that won't parse or a key that fails to import → `error: "incomplete"`.
  - Envelopes that fail `open`, `isGroupRecord` or `sanitizeMember` are skipped, with `console.warn`.
